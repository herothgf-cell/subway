구현: 43역이 8개 구간 중 하나를 갖는다. 기존 승객 유형(대학생, 직장인, 등산객, 서류 봉투, 학생, 쇼핑백)이 구간별·예외 역별 하차 가중치를 갖는다. 환승 검색 승객은 환승 등급으로 내린다. 한강 구간은 주행 시간 1.6배에 덜컹거림이 없다. / 보류: 구간 전용 승객 유형(IT 직장인, 야구 유니폼, 가족 나들이, 캐리어, 관광객, 악기 가방), 역별 승차 급증(신도림 대량 승차, 경기 있는 날 종합운동장), 도심의 짧은 정거장 간격, 주말 저녁 혼잡, 한강 창밖 연출. / 다르게 구현: 종합운동장 인파는 주말 약속 "야구 관람"의 귀가길 혼잡 ×1.4로만 있다(04).

4. 순환선 규칙 (3단계) 보류

지금은 늘 짧은 방향으로 탄다(같은 거리면 내선). 방향 고르기, 돌아가기, 두 경로 비교는 없다.

  • 승강장에서 내선 / 외선을 고른다. 기본은 짧은 방향이다.
  • 돌아가기: 먼 방향을 타면 정거장이 훨씬 많지만 한산한 구간을 지난다. 대신 도착 시각이 늦어져 지각 위험이 생긴다 (04 일정의 도착 시한).
  • J 성격 표현: 플래너에 두 경로의 예상 소요 시간과 혼잡도를 미리 보여 주고 고르게 한다.

5. 역 데이터 구조 구현됨

다르게 구현: 역(LINE2)은 이름, 구간(zone), 환승 노선(tr), 등급(grade), 구간 길이(gap)를 갖는다. id는 없고 역 이름이 키다. 하차 가중치(alight)는 역이 아니라 승객 유형 쪽(ARCH, ARCH_Z)에 출근·퇴근별로 둔다. 주말은 퇴근 값을 쓴다. 기존 신림~강남 9역은 원래 값을 그대로 쓴다.

{
  id: "sadang", name: "사당",
  transfer: ["4"],          // 환승 노선. 물갈이 등급 계산에 사용 (05 문서)
  grade: "S",               // 환승 등급 S/A/B/없음
  zone: "gwanak",           // 구간 (승객 유형 가중치)
  gap: 1.0,                 // 다음 역까지 구간 길이 배수
  alight: { am: {...}, pm: {...}, weekend: {...} }  // 승객 유형별 하차 가중치
}
  • 현재 코드는 STATIONS 배열과 승객 유형(ARCH)마다 역 이름으로 가중치를 적는 방식이다. 역이 43개가 되면 유형마다 역을 다 적을 수 없으므로, 역이 구간을 갖고 승객 유형이 구간별 가중치를 갖는 구조로 바꾼다.
  • 특정 역에만 해당하는 유형(과잠 → 서울대입구)은 예외 항목으로 덧붙인다.

6. 노선도 UI 일부 구현

구현: 통근 중 상단 노선도는 내 구간만 직선으로(10정거장이 넘으면 가까운 역만 이름 표시). 캐릭터 선택 카드에 원형 노선도와 집·회사 핀. / 보류: 일정 화면의 원형 노선도, 약속 장소 핀.

  • 통근 중 상단 노선도는 현재처럼 내 구간만 직선으로 보여 준다.
  • 캐릭터 선택과 일정 화면에서는 순환선 전체를 원형으로 보여 주고 집·회사·약속 장소를 핀으로 찍는다.

8. 1차 구현 내용 (2026-11-24) 구현됨
