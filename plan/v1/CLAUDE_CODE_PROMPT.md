## 작업 규칙

### 0. 미결 사항은 서로 검토하고 제안해서 결정한다
- 각 기획서 끝의 "미결 사항"은 확정된 것이 아니야. 임의로 정해서 구현하지 마.
- 어떤 기획서를 구현하기 전에 그 문서의 미결 사항을 다음 순서로 처리해.
  1. 미결 사항을 관련 코드 현황과 함께 정리
  2. 항목마다 선택지 2~3개, 추천안, 근거(구현 비용, 플레이 영향)를 제시
  3. 내 결정을 기다림. 내가 다른 안을 내면 그 안의 문제점도 솔직하게 검토해 줘
  4. 결정을 `plan/v1/DECISIONS.md`에 기록 (날짜, 문서 번호, 항목, 결정, 이유)하고 해당 기획서 HTML 본문에도 반영
  5. 그다음에 구현
- 기획서 본문에서도 모호하거나 서로 충돌하는 규칙을 발견하면 같은 방식으로 물어봐.
- 기획서의 수치는 전부 조정 전 가정값이야. 기존 스킬 7종의 비용·효과만 현재 코드 값이야.

### 1. 인트로(01)는 시안 흐름 확인 후 개발
- 게임 코드에 넣기 전에 `intro-flow.html`(단독 파일, 클릭으로 넘기는 스토리보드)로 컷 ①~⑤와 타이틀 화면 시안을 먼저 만들어 보여 줘.
- 내가 흐름·문구·구도를 확정한 뒤에만 `index.html`에 구현해.

### 2. 캐릭터 능력치(02)의 균형과 버티기
- 능력치는 6종이야. 밀림은 원인에 따라 둘로 나눠: 열차가 만드는 밀림(급정거·출발·덜컹거림)은 **균형**, 사람이 만드는 밀림(다른 승객이 부딪힘, 하차 인파, 쓸려 내림)은 **버티기**. 02 문서의 "균형과 버티기의 구분" 표가 기준이야.
- 손잡이(Shift)는 균형 쪽 밀림은 완전히 막고, 버티기 쪽 밀림은 절반만 막아. 이건 결정된 규칙이야.
- 현재 코드는 급정거(`jolts`)에만 균형 감각 스킬이 걸려 있고, 승객과 겹칠 때는 균등하게 밀어내며 손잡이와 무관해. 버티기와 손잡이 절반 규칙을 어떻게 넣을지 구현 전에 제안해 줘.

### 3. 구현 순서
`plan/v1/index.html`의 "제안 도입 순서"를 기본으로 하되, 첫 보고 때 네 의견을 줘.
1. 12 오늘의 계획표, 05 환승역 물갈이
2. 07 시선 눈치, 06 특수 승객(백팩·넓게 앉기부터), 08 회사·집 이벤트
3. 09 스킬 확장, 10 아이템
4. 03 노선 확장 → 02 캐릭터 → 04 일정 → 13 동행·출근 일기·계절 → 01 인트로 개발
5. 11 좌석 등급

인트로 시안(`intro-flow.html`)은 1단계와 병행해서 먼저 보여 줘도 돼.

### 4. 구현 방식
- 기획서 한 건(또는 그 안의 한 단계)씩 구현하고, 건마다 커밋해. 커밋 메시지는 기존처럼 한국어로.
- 기존 저장 데이터(localStorage 프로필)가 깨지지 않게 해. 구조를 바꾸면 이전 값을 옮기는 처리를 넣어.
- 새 규칙을 넣을 때마다 기존 난이도가 어떻게 바뀌는지 자동 시뮬레이션이나 헤드리스 실행으로 확인하고, 결과 수치를 보고해 줘. 직접 실행해 보지 않은 것은 확인했다고 하지 마.
- 건마다 끝나면 무엇을 구현했고, 기획서와 다르게 한 곳과 그 이유, 내가 직접 플레이해서 확인할 점을 알려 줘.
- 구현이 끝난 기획은 `PLAN.md`에 반영해서 PLAN.md를 v3로 올려 줘.
- 불쾌감을 줄 수 있는 소재(취객, 시선·오해, 동행 매너)는 기획서의 원칙대로 행동 기준으로 표현하고 코믹한 수위를 유지해.
